## 🎯 О проекте

**Тема:** Buy or Bye: купит или уйдёт?

**Уровень сложности:** BASE

**Трек:** ML (классический ML с последующим внедрением DL)


Датасет описывает каждую пользовательскую сессию уже **агрегированным вектором**: число посещённых страниц, длительности, bounce/exit rate и другие показатели. Проект классифицирует такой зафиксированный «снимок» сессии, а не строит потоковый прогноз по каждому клику.

**Цель:** разработать воспроизводимый классификатор целевой переменной `Revenue` (закончилась ли сессия покупкой) и сервис для скоринга одной агрегированной записи пользовательской сессии.

Так как проект уровня BASE, основной акцент сделан на **сервисной и инженерной части**: воспроизводимый pipeline, REST API, валидация входных данных, тесты, трекинг экспериментов.

**Задачи:**

- провести EDA и выявить, какие сессии чаще заканчиваются покупкой;
- обучить и сравнить Dummy, Logistic Regression, CatBoost и MLP;
- учесть дисбаланс классов (class weights, подбор порога) и не опираться на одну accuracy;
- отдельно оценить качество для новых и возвращающихся посетителей;
- реализовать сервис на FastAPI (с демонстрационной формой на Streamlit), с валидацией и pytest-тестами;
- настроить MLflow и воспроизводимость экспериментов.

## ⚠️ Важное ограничение

Исходные данные **не являются последовательностью кликов**. Сервис демонстрирует скоринг готового вектора сессии и **не является ранним real-time предсказанием**. Признак `PageValues` оценивается только в отдельной модели, чтобы исключить возможную утечку информации о целевой переменной.

---

## 📏 Метрики качества

| Метрика | Зачем |
|---------|-------|
| **PR-AUC** | основная метрика при дисбалансе классов |
| **F1-score** | баланс precision и recall |
| **ROC-AUC** | общая разделяющая способность |
| **Recall** (класс «покупка») | доля найденных покупателей |
| **Precision** (класс «покупка») | доля верных срабатываний |

Одной accuracy ограничиваться не будем: классы несбалансированы.
